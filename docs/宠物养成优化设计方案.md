## 一、现状评估

### 1.1 现有资产盘点

| 资产 | 位置 | 现状 |
|------|------|------|
| 系列/物种/等级数据 | `frontend-vue/src/utils/petData.ts` | ✅ 8 系列、54 物种、每物种 12 级,有名称/描述/阶段/所需积分 |
| 场景配置 | `petData.ts` 的 `SERIES_SCENES` | ✅ 每系列主题色/渐变背景/装饰 emoji/场景名 |
| 宠物展示 | `PetDisplay.vue` | ⚠️ **用 Emoji 当主体,12 级共用同一 emoji,视觉不随等级变化** |

| 进化图鉴 | `PetHandbook.vue` | ⚠️ 里程碑预览仍是 emoji,无每阶段形象 |
| 诗文/台词 | `petHandbookData.ts` | ✅ 每物种 6 阶段诗文 + 进化台词(质量很高,是亮点) |

| 后端接口 | `TeacherController` | ❌ 读取 `$p->species` / `$p->exp`(表里没有这两列)→ **返回 null,前后端契约断裂** |

### 1.2 核心问题清单(按严重度排序)

#### 🔴 P0 · 数据契约断裂(必须修)
1. **前后端字段不一致**:`pets` 表只有 `type`,控制器读 `species`/`exp` 得到 `null`。前端 `loadPets()` 拿到的 `species` 全是 null,会 fallback 到 `myth` 系列 → 全班宠物显示错乱、投喂/改名接口也读不到正确字段。
2. **两套宠物体系并存**:前端是"8 系列 54 物种 × 12 级",后端 `Pet.php` 是"`type` 字典 + 10 级进化表"。切换宠物 `switchPet` 用 `pet_type`(如 `stellar_cat`/`pikachu`),前端根本不知道这些类型。需要统一为一个数据源。
3. **进化/成长逻辑重复且冲突**:前端按累计积分阈值(0/15/35/60…)给 12 级;后端 `syncLevelWithScore()` 有一份不同的阈值表(0/15/41/68…)。两边都不对齐,且前端 `getLevelRequiredScore` 数组实际是 0/15/41/68…(50 个元素),与文本描述阈值也不一致。

#### 🔴 P1 · 展示短板(用户核心诉求)
4. **宠物主体是 Emoji 而非 SVG**:`PetDisplay.vue` 的 `.pet-emoji-main` 渲染 `getSpeciesEmoji(speciesId)`——**一个物种 12 个等级长得一模一样**,只有文字名称/描述变化。用户要求"每个阶段用 SVG 绘制且生动有趣",这是最需要重做的部分。
5. **无进化视觉反馈**:等级提升没有体型/颜色/部件变化,缺少"进化瞬间"的视觉冲击(可参考宠物蛋→破壳→成形的表现力)。

#### 🟠 P2 · 玩法深度不足
6. **每系列物种不足 12 种**:除星座(12)外,其余 7 个系列都只有 6 种 → 总量 54。用户要求每系列至少 12 种。
7. **进化路线单一**:基本全是线性 12 级(积分到了就升),只有"伊布"有分支但也是写死进名称里,无路线元数据、无分支条件、无融合玩法。
8. **无切换规则与限制体系**:虽有 `switchPet`(切 type、扣 5 经验),但无"解锁条件 / 冷却 / 进度保留 / 图鉴收集"设计;数据库一对一结构也不支持"宠物图鉴收藏"玩法。
9. **缺少角色性格设定**:现有 description 全是"形态视觉描述",没有每阶段的"性格/行为/能力"特点。用户要求"成长各个阶段的宠物角色特点说明"。
10. **缺少趣味联结叙事**:除 `petHandbookData.ts` 的诗文外,没有系列主题向的流行文化/经典联结。用户要求星座↔圣斗士、传统节日↔诗词典故等。

#### 🟡 P3 · 工程与版权
11. **外链依赖**:后端 `evolutionStages()` 用 DiceBear 外链图片(`https://api.dicebear.com/...`),离线/自托管环境失效,且与 SVG 化目标冲突。
12. **版权命名残留**:后端 `petTypes()` 直接出现 `pikachu/eevee/charmander/mewtwo/snorlax/gengar/charizard` 等版权角色键名。项目非商用故风险可控,但建议在统一数据源时换成原创名(如"火元素·熔岩蜥"),既避免纠纷也便于 SVG 原创绘制。

### 1.3 评估结论

> 现状是"**内容厚、玩法薄、契约断、展示弱**":
> - **内容** 足够丰富(54 物种 × 12 级 × 诗文台词),是很好的素材底座;
> - **玩法** 只是"积分到→升级→显示更高等级的 emoji",缺乏养成深度;
> - **契约** 前后端两套体系未打通,当前宠物功能实际是演示态;
> - **展示** 是最大短板——Emoji 无法承载 12 级×96 物种的"生动有趣"。
>
> 优化方向 = 统一数据契约 + 扩到每系列 12 种 + 补全进化/切换规则 + 补全阶段角色设定 + 建立 SVG 绘制体系。

### 2.2 数据模型重构(单一数据源)

**方向**:以 `petData.ts` 为**唯一事实来源**,后端不再维护第二套 `evolutionStages()`,宠物数据全部由前端类型定义 + 后端只存"状态",或后端引用同一份数据(方案 A 前后端共用 JSON,方案 B 后端只存状态)。

**前端 `PetSpecies` 扩展**(建议字段):

```ts
export interface PetLevel {
  level: number            // 1-12
  name: string
  description: string      // 形态视觉描述
  personality: string      // ✨角色性格特点(本阶段新增)
  ability: string          // ✨本阶段能力/技能
  motto: string            // ✨本阶段口头禅/台词(进化和图鉴用)
  stage: 'egg'|'baby'|'growing'|'mature'|'legendary'
  requiredScore: number
  /** SVG 参数(见第五章) */
  art?: {
    body: string           // 身体部件键
    color: string          // 主色
    accessory?: string[]   // 装饰件(角/翼/光环/圣衣等)
    scale?: number         // 体型放大系数
    glow?: number          // 光晕强度 0-100
    fx?: string[]          // 特效(火焰/雷电/星尘/数据流…)
  }
}

export interface PetSpecies {
  id: string
  name: string
  seriesId: string
  /** ✨进化路线元数据(新增) */
  route: 'linear' | 'branch' | 'fusion'
  branches?: { fromLevel: number; to: string[]; condition: string }[]
  /** ✨切换限制(新增) */
  switch?: {
    unlockLevel: number    // 达到该物种几级后允许切走
    costScore: number      // 切换消耗积分
    cooldownDays: number   // 切换冷却
    keepExp: boolean       // 是否保留经验
  }
  levels: PetLevel[]
}
```

**数据库**:新增 `pet_collections` 表(学生×物种收藏,记录各自等级/经验/心情),`pets` 表保留为"当前激活宠物"(加 `species` 列),并做迁移补齐 `species` 列 + 清洗旧 `type` 数据。

### 2.3 阶段体系(12 级 × 5 阶段)

沿用现有 `egg → baby → growing → mature → legendary`,但每个阶段要**同时具备三种文本**:视觉描述、性格特点、能力/口头禅;并由 SVG 参数驱动**视觉逐级变化**(见第五章)。

| 阶段 | 等级 | 性格基调 | 视觉基调 |
|------|------|----------|----------|
| 卵生 | Lv.1-2 | 期待、懵懂、脆弱 | 蛋/种子/核心,微微脉动发光 |

## 三、进化路线规则设计

### 3.1 三种路线类型

1. **线性进化(Linear)**:一条主线 12 级,前后有清晰的体型/性格成长弧线。适合大多数物种(默认)。
2. **分支进化(Branch)**:到达指定等级(如 Lv.6)时,根据**养成行为**选择方向,此后 6 级走不同形态与性格。参考现有"伊布",但把条件实体化。
3. **融合进化(Fusion)**:两条分支在 Lv.9+ 融合为"究极形态"(如 火×风=风暴龙),需要同时满足两个分支的成就。

### 3.2 分支/融合条件(可量化的养成行为)

| 条件类型 | 示例 |
|----------|------|
| 行为倾向 | 投喂次数 / 加分方向(学习币 vs 读书币) |
| 成就解锁 | 连续连击天数、考勤全勤、作业提交率 |
| 属性达标 | 心情值、专注值、某科目积分 |
| 时间条件 | 只在特定节日/季节可进化(如年兽腊月觉醒) |

> 落地建议:第一版**只做线性**,把分支/融合作为数据模型预留(`route`/`branches` 字段),玩法后续迭代再启用。

### 3.3 各系列主题联结(趣味性)

| 系列 | 联结主题 | 玩法/命名彩蛋 |
|------|----------|---------------|
| 星座守护 | **圣斗士星矢** | 进化 = 圣衣进化(青铜→白银→黄金→神圣衣);12 宫致敬"穆/阿鲁迪巴/撒加…";燃烧小宇宙、第七感 |

## 四、切换规则与限制

> 核心目标:让"图鉴收集 + 养成选择"成为长期动力,同时限制反复横跳。

### 4.1 解锁规则
- **初始 1 只**:注册/建档后自动获得第 1 只(默认"星尘"或随机)。
- **图鉴解锁**:其余物种通过 **成就 / 积分里程碑 / 节日活动** 解锁,加入"图鉴收藏"。
  - 积分每满 100 解锁一个图鉴槽位;
  - 指定成就(如全勤一周)解锁稀有物种。

### 4.2 切换成本与冷却
| 参数 | 建议值 | 说明 |
|------|--------|------|
| 切换消耗 | 5 成长值(积分) | 与现状 `switchPet` 一致,防滥用 |
| 冷却时间 | 7 天 | 一周最多合理切换一次;节日活动可临时 1 天 |
| 目标校验 | 仅可切换**已解锁**物种 | 未解锁则提示"还需 N 分解锁" |
| 唯一性 | 同一物种全班不限制 | 但**一个学生同时只激活 1 只** |

### 4.3 进度保留策略(关键决策)
| 方案 | 行为 | 适合 |
|------|------|------|
| A · 全保留 | 切走后原物种等级/经验/心情**永久保存**,切回时恢复 | 收集型玩法,无挫败感 ✅ 推荐 |
| B · 降级保留 | 切走扣一定经验(如降 1 级) | 有取舍感,较硬核 |
| C · 全清零 | 切走即清空 | 过度惩罚,不推荐 |

> 推荐 **A 全保留**,配合 7 天冷却,既鼓励尝试新物种,又不惩罚探索。

### 4.4 图鉴 / 宿舍系统
- 新建「宠物图鉴」视图(已有 `PetHandbook.vue` 雏形),展示:
  - 已解锁物种数 / 总数(108);
  - 每物种已收集的最高形态(点亮图鉴卡片);
  - 未解锁物种的"解锁条件"提示。
- 前端数据流:`pet_collections` 表 + `pets`(激活宠物),教师端 `PetsPage` 展示全班激活宠物 + 每名学生图鉴进度。

## 五、SVG 绘制体系方案

> 目标:每个等级都有**专属 SVG 形象**,生动有趣、逐级渐变、可动画、可离线。

### 5.1 架构(组件 + 数据驱动,而非 108×12 张死图)

```
PetSprite.vue (新组件)
 ├─ 输入: speciesId, level, mood, animate, size
 ├─ 解析: getLevelArt(speciesId, level) → PetLevel['art']
 └─ 输出: 内联 <svg> 分层渲染
      ├─ defs(渐变/滤镜/发光)
      ├─ 身体部件(<g>): 由 art.body 指定部件模板
      ├─ 阶段修饰: 蛋壳/幼体 Q 版/成体部件/圣衣/光环
      ├─ 特效层: 火焰/雷电/星尘/数据流(SMIL 动画)
      └─ 表情层: 眼睛/嘴随 mood 切换
```

- **部件库**:`src/utils/petArtParts.ts` 提供基础几何部件(圆身/椭圆身/三角头/角/翼/尾/光环/圣衣肩甲…),按 `body` 键组合。
- **逐级变化参数**:`art.scale`(体型)、`art.color`(主色随等级加深)、`art.glow`(发光强度)、`art.fx`(特效数量)——**同一部件模板 + 参数渐变 = 12 个不同观感形态**,成本远低于逐级手绘。
- **关键形态跃迁**:Lv.2 破壳(蛋壳裂开)、Lv.6 部件成形(角/翼/圣衣出现)、Lv.9 完全体、Lv.12 究极(光环+全屏特效)。这 4 个跃迁点做**专属装饰层**,保证"进化瞬间"有视觉冲击。

### 5.2 每阶段视觉语言

| 阶段 | SVG 表达 |
|------|----------|
| 卵生 | 椭圆蛋 + 裂纹/脉动光晕 + 内影轮廓;动画:轻微呼吸起伏 |
| 幼年 | 大头小身 Q 版、圆眼大而亮、四肢短、腮红;动画:眨眼/摇晃 |

> 圣衣进化模板(12 级):Lv.1 小宇宙之种 → Lv.2-3 圣斗士候补 → Lv.4-5 **青铜圣衣** → Lv.6 **白银圣衣** → Lv.7-8 **黄金圣衣初现** → Lv.9-10 **黄金圣斗士**(完全觉醒) → Lv.11 **第七感**(燃烧小宇宙) → Lv.12 **神圣衣**(超越女神之光)。

### 6.10 七侠剑客系列 × 虹猫蓝兔七侠传(12)⭐ 武侠热血联结
