# 系统架构与端口（三端口模型）

> 版本：2026-08-06
> 定位：学趣星球是学校老师上课规范学生行为、养成学习习惯的班级管理工具。
> 本次确立三端口模型，移除家长端。

---

## 一、端口总览（共 3 个）

| 端口 | 进入方式 | 前端入口 | 后端 API 前缀 | 定位 |
|------|----------|----------|---------------|------|
| **管理员端** | 管理员账号密码 | `/admin`（AdminLayout） | `/api/v1/admin/*` | 学校/班级/教师/学生/积分规则/商品/报表/学年升级 |
| **教师端** | 教师账号/第三方扫码 | `/teacher`（TeacherLayout） | `/api/v1/teacher/*` | 班级端的高级功能入口：积分、宠物、排行榜、作业、测验、考勤等 |
| **教室端** | **班级码**（唯一入口） | `/classroom`（ClassroomLayout） | `/api/v1/auth/class/login` + `/api/v1/display/*` | 学生/班级共用的大屏与课堂互动（班级为单元） |

> 登录页提供三个 Tab：教师 / 管理员 / 🔑 班级码。

## 二、关键澄清：学生端/班级端/教室端 = 教室端

- 所谓「学生端」「班级端」「教室端」在实现上**是同一个端口**——**教室端**。
- **以教室为一个单元**：学生隶属于班级，所有课堂行为（积分、宠物、榜单、PK、AI）都以班级为作用域。
- 唯一进入方式：**班级码** → `/classroom`。
- 教师端内以「基础模式」（`meta.basic`）复用同一套教室页面（Overview/Scores/PK/Pokedex/AI），教师可一键切换进入教室端。

## 四、兑换体系（汇率 / 奖励 / 惩罚）的管理与同步

### 4.1 数据归属
| 数据 | 表 | 作用域 | 管理方 |
|------|-----|--------|--------|
| 汇率 | `exchange_rates` | **school 级** | 教师 + 管理员（同一张表，共享） |
| 奖励商品 | `shop_items` | school 级(`class_id=null`) + 班级级 | 教师建班级级；管理员建/改学校级 |
| 惩罚规则 | `score_rules`(负分) | school 级 + 班级级 | 教师 + 管理员 |

### 4.2 管理员聚合 + 同步（本次实现）
- **聚合**：`adminListShopItems` 现返回全校所有商品（学校级 + 教师创建的班级级，附 `class_name` 与 `scope`），管理员可据此统一查看、优化。
- **同步**：管理员创建/修改**学校级**商品或汇率后，因 `listShopItems`/`listExchangeRates` 均按 `school_id` 读取，**自动同步到该校所有班级 / 所有教师端**，无需手动下发。
- **默认方案**：迁移 `2026_08_06_000007` 为每个学校播种默认奖励商品（集体观影/免作业/免做卫生/免罚站/免罚跑步 + 铅笔/圆珠笔/橡皮/便利贴/草稿纸/练习本/饮料/水果/3D 打印作品）与默认惩罚规则（迟到/讲话/未交作业/打架等负分），并把汇率统一为 **1:1**（积分→科学币/读书币/体育币）。

### 4.3 汇率口径
- 四个币种：⭐ 积分(score) / 🔬 科学币(science) / 📚 读书币(reading) / ⚽ 体育币(class_point)，**兑换比例统一 1:1**。

## 五、数据流（以教室为单元）

```
班级码 ──> 教室端(/classroom)
              │ 以 class_id 为作用域
              ├─ 积分/排行榜/宠物/图鉴/PK/AI
              │
教师账号 ──> 教师端(/teacher) ──管理本班──> 同一批 class_id
管理员账号 ─> 管理员端(/admin) ──配置学校/班级/账号
```

- 学生没有独立登录；进入教室端即代表「该教室的一个学生/成员」。
- 教师是教室端的高级操作入口，管理的是**同一个教室单元**。
